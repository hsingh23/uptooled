# 003 — Netlify build-time generation, no CI workflow

- **Date:** 2025-06-08
- **Commits:** `9a3a124` (external generator in CI), `0e8de65` (merge
  generators, move to Netlify); earlier `c2147be`/`f2d06fb` (CNAME
  add/remove on GitHub Pages)
- **Status:** Accepted

## Context

Initially the catalog was regenerated by a GitHub Action that committed
`tools.json` back to the repo (needing `permissions: contents: write`).
A CNAME briefly pointed GitHub Pages at `tools.roomtolearn.org` before
being dropped the same day.

## Decision

Move hosting to **Netlify**: `netlify.toml` runs `node generate.js` at
deploy time and publishes the repo root. The GitHub Actions workflow and
the split generator scripts (`generate-tools.js`,
`generate-external-sites.js`) are deleted in favor of a single
`generate.js`.

## Alternatives

- Keep GitHub Actions committing generated files — rejected: noisy bot
  commits and permission fixes; the repo already carries several
  "github-actions Update tools.json" artifacts from this era.
- Precompute locally and commit — rejected: easy to forget.

## Consequences

- `tools.json`/`external-sites.json` in the repo are snapshots; Netlify's
  deploy may differ if sources changed without a local regenerate.
- No CI at all today — no automated checks on push.
- One fewer moving part; deploys are fast and cheap.
